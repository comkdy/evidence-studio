# 대화하며 연구 보고서 작성

연구 질문 화면에서 AI 대화와 보고서를 나란히 엽니다. 좁은 화면은 **AI 대화 / 보고서** 탭으로 전환합니다. 기존 질문·전문가 선택·진행 단계·중지·대화 다시 열기는 유지합니다.

1. **새 보고서**에서 제목과 목적을 입력합니다. 핵심 요약, 주요 결과, 비교와 조건, 적용 한계와 후속 검토의 빈 구간을 만듭니다.
2. 먼저 연구 질문으로 논문 근거를 확보합니다. 보고서 구간을 선택하고 **구간 질문**으로 내용·조건·근거를 묻거나, **구간 수정**으로 해당 구간의 초안·편집을 요청합니다. 구간 질문은 보고서를 변경하지 않습니다.
3. 수정 시 기본적으로 현재 구간과 앞선 완료 답변의 근거를 재사용합니다. **추가 논문 조사**를 켜면 선택한 전문가 또는 자동 추천 전문가의 범위에서 새 근거를 찾습니다.
4. 각 구간의 **출처 확인**에서 작성 당시 논문·원문 인용·페이지를 확인합니다. 제목·표시 형식(본문/핵심 항목/비교 표)을 바꾸거나 구간을 추가·삭제할 수 있습니다. 이 작업은 LLM을 호출하지 않습니다.
5. **변경 이력**에서 이전 버전을 미리 보고 복원합니다. 복원은 과거 이력을 지우지 않고 새 버전으로 저장합니다. **HTML 다운로드**는 현재 화면에서 선택한 버전을 내보냅니다.

## 입력과 저장 범위

편집 모델에는 보고서 제목·목적·제목으로 구성된 목차, **선택한 한 구간의 본문**, 해당 구간의 근거와 본인 소유 완료 답변 최대 6개의 근거 후보만 전달합니다. 다른 구간 본문·전체 대화·전체 논문을 매번 보내지 않습니다. 모델 입력 예산에 들어오는 후보 최대 24개를 선별하며 기존 구간 인용은 임의로 버리지 않습니다. 기존 구간 자체가 예산을 넘으면 구간 분리/모델 한도 확인을 안내하고 저장하지 않습니다.

추가 조사를 끈 편집은 LLM 생성 1회이며 실패 시 자동 재호출하지 않습니다. 추가 조사는 기존 심층 QA의 계획·검색·답변·검토 호출에 구간 편집 1회가 더해집니다. 따라서 새 근거가 필요한 경우에만 켭니다. 기존 `.env`의 LLM·검색 설정 및 공유 호출 제한을 사용하며 보고서 전용 API key는 필요 없습니다. 공통 Wiki 작성 지침과 용어 사전을 읽되 작업 계약은 `backend/prompts/report_edit.txt`에 둡니다.

SQLite `reports`에는 작성자·제목·현재 revision을, `report_versions`에는 본문 JSON·근거 사본·요청·모델·편집 사용량·시점을 저장합니다. 구간 ID는 수정·복원 후에도 유지합니다. 첫 서버 시작 시 테이블만 추가하며 기존 DB/Wiki 데이터는 유지합니다. 보고서는 작성자만 열람·수정·내보낼 수 있습니다. 관리자도 다른 작성자의 보고서를 우회 열람하지 않습니다. 대화 목록은 기존처럼 브라우저에 저장되고, 보고서 자체는 서버에 저장되어 보고서 목록에서 다시 열 수 있습니다.

LLM 호출 동안 DB 쓰기 트랜잭션을 열지 않습니다. 저장 직전에 revision을 비교하며 다른 탭이 먼저 저장했다면 409로 거부합니다. 이때 **새로고침**으로 최신 내용을 열고 다시 요청합니다. 연결 종료·중지는 다음 단계와 저장을 취소합니다. 이미 외부 API에 전달된 연산 자체의 취소는 보장하지 않으며, 완료 저장이 중지보다 먼저 일어났다면 최신 버전에서 확인할 수 있습니다.

## 근거와 출력

모델은 HTML 대신 구조화된 진술을 반환합니다. 원문 위치·표기 정규화·수치/단위 검증을 기존 QA와 공유하고 실패하면 기존 보고서를 유지합니다. 논문 근거·종합 해석·검증 전 가설·제안 실험을 구분합니다. 초안이나 사용자 발언을 새로운 원천 근거로 승격하지 않으며 보고서를 canonical claim/수치나 Wiki ingest에 자동 재투입하지 않습니다.

HTML은 서버 템플릿이 이스케이프한 내용과 인라인 CSS로 만듭니다. 외부 이미지·스크립트·CDN 의존성이 없고 인용 번호가 문서 하단의 근거 사본으로 연결됩니다. 앱 화면에서는 논문 상세와 원문 PDF도 확인할 수 있습니다. 인용 위치와 수치 검증은 과학적 타당성·비교 가능성을 모두 증명하는 절차가 아니므로 공유 전 사람의 검토가 필요합니다.

보고서 버전의 `usage`는 편집 호출과 제공자 token 사용량, 경과 시간, 추가 조사 실행 ID를 보관합니다. 추가 조사 모델 호출 정보는 해당 `answer_runs` trace에 별도로 남습니다. 보고서의 근거는 작성 시점 사본이므로 논문 수정 시 자동으로 덮어쓰지 않습니다.

## API와 검증

- `GET/POST /api/pilot/reports`: 내 보고서 목록/생성.
- `GET /api/pilot/reports/{id}?version=N`: 현재/이전 버전.
- `PATCH .../{id}/sections`: 구간 추가·제목/형식 수정·삭제.
- `POST .../{id}/edit-stream`: 구간 수정. 실제 처리 `progress`와 검증 후 `report_result`를 NDJSON으로 전송.
- `GET .../{id}/versions?before=N`, `POST .../{id}/restore`: 이력/복원.
- `GET .../{id}/export?revision=N`: 해당 버전 HTML.
- 기존 `/ask-stream` 및 `/ask`는 선택적으로 `report_id`, `report_section_id`, `report_revision`을 받아 선택 구간을 질문 문맥에 추가합니다.

`tests/test_reports.py`와 `tests/report-workspace.test.mjs`는 소유권·선택 구간만 수정·원문/수치 검증·동시 수정·중지·버전 복원·HTML 이스케이프·기존 대화 호환을 확인합니다. `python -m backend.diagnostics --steps unit`의 HTML 보고서에 포함됩니다. 테스트 모델의 성공과 사내 실제 LLM의 응답 품질/속도는 별도로 확인해야 합니다.
