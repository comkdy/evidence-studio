# Pilot과 제품 목업 비교 · 2026-10-13

**추가 보완:** 전문가 설정의 '전문가 추가'를 실제 DB 저장으로 복원했다. 이름·개요·분류 전체 선택 기본값, 편입 미리보기, 애매한 논문 직접 편입·제외, 활성 여부, 생성 후 Wiki 연결을 제공한다. 공통 claim·수치·Wiki 본문을 재사용하며 정책에 따라 새 논문 소속을 갱신한다. 이후 기존 전문가 설정 조회·수정 팝업도 연결했다. 카드는 여백을 줄이고 '설정 확인·수정'과 '전문가 지식' 버튼으로 통일했다. 개요로 분류 추천은 아직 미연결이다. 라이브러리에는 Report AI를 참고한 오른쪽 5축 카테고리 패널, 후보 수, 선택 칩, 초기화와 모바일 패널을 추가했다. 아래 표의 읽기 전용·생성 미연결 항목은 이 변경 전 기록이다.

검증: SQLite 임시 DB 회귀 테스트 18개와 TypeScript·Vite 빌드 통과. 실제 41편 DB의 별도 검증 복사본에서 DRAM Reliability 생성 → 담당 논문 1편·claim 3개·Wiki 1개 연결 → 새로고침 후 저장 유지를 확인했다. 라이브러리 OR/AND 필터·페이지 초기화·전체 초기화·모바일 열기/선택/닫기를 확인했고 브라우저 경고·오류는 없었다. 원래 DB는 테스트 전문가 없이 보존했으며 논문·claim·수치·조건·Wiki·기존 전문가 소속을 작업 전 백업과 비교해 동일함을 확인했다.

후속 사용자 요청에 따라 앱을 실제 DB 화면 하나로 통일했다. 왼쪽의 '실제 논문 시범'과 DB 확인, 상단 Pilot·목업 비교, 사용 가이드의 구현 비교표를 제거했다. 아래는 통합 전 비교 기록이며 개발 검토용으로 남긴다. 기존 `#pilot/*` 주소는 일반 앱 주소로 변환되고 기존 가상 `App.tsx`는 기본 앱에 포함하지 않는다. 전문가 생성·분류 편집으로 가는 목업 링크는 제거했다. 업로드는 아직 연결되지 않아 비활성화했다.

원래 Pilot에는 상단 개발용 탐색만 있고 왼쪽 제품 주메뉴와 개인·팀 동선이 없었다. 기존 목업을 비교해 아래처럼 복원했다. 실제 자료의 탐색과 근거 연결을 우선하며 운영 시스템을 추가하지 않았다.

기존 목업은 `#ask` 등에서 계속 볼 수 있고 Pilot은 `#pilot/*`에서 열린다. 상단 '목업 비교'와 전문가 설정의 '기존 설정 목업'은 다른 가상 데이터 화면으로 이동하므로 세션의 Pilot 검색 기록은 다시 초기화된다. 이 이동이 실제 DB 설정을 변경하지는 않는다.

## 검증

Python 테스트는 전문가 범위 합집합, unknown expert 제외, Wiki 공유 범위, 지연 조회·페이지 이동, 근거 유일 일치와 숫자 보존, 제목 교정 이력·FTS 반영, 잘못된 연결 및 적재 롤백을 검사한다. 기존 목업 테스트는 claim 선택·수치 연결·Wiki의 회귀를 검사한다.

브라우저 검증: 실제 claim·수치 조회, 전문가 선택, Wiki 주제와 근거 페이지 이동, private 질문의 팀 목록 제외, 삭제 후 private 상태 복구, 북마크와 논문 상세, 상단 닫기, 자료 현황·전문가 설정·모바일 메뉴. 자세한 DB 결과는 [논문별 적재 기록](CORPUS_REVIEW_2026-10-13.md)을 참고한다.
