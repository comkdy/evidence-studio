# Evidence Studio 전문 용어 표기 기준

설명과 일반 UI는 한국어로 작성하고, 반도체 전문 용어는 영어로 유지합니다. 번역 때문에 개념이 바뀌거나 같은 용어가 여러 표현으로 흩어지는 것을 방지하기 위한 기준입니다.

## 표시와 인용

- 답변, 주장 요약, 지표·조건명, 전문가의 담당 분야에 동일한 영어 표기를 사용합니다.
- 원문 인용, 논문 제목, 저자, 수식, 변수, 단위, 부등호는 원문대로 보존합니다. 사전의 대표 표기가 달라도 인용문을 고치지 않습니다.
- `retention time`, `refresh interval`, `charge trapping`, `bandwidth`, `correction latency`처럼 원문 용어를 한국어 설명 안에 배치합니다.
- DRAM, NAND, HBM, ECC, RBER 등의 약어는 유지합니다. 약어의 의미가 원문에서 확인되지 않으면 임의로 풀어 쓰지 않습니다.
- 같은 개념임이 확인된 표현만 대표 용어에 연결합니다. `retention`과 `endurance`, `refresh interval`과 `retention time`은 서로 합치지 않습니다.
- 문맥에 따라 의미가 달라지거나 사전에 없는 용어는 원문 표기를 유지하고 검토 대상으로 남깁니다. 한국어로 뜻을 추측해 대체하지 않습니다.
- `may`, `at least`, 부정 표현 등 주장의 강도와 적용 조건은 영어 용어 통일과 별개로 보존합니다.

예: “DRAM-A의 retention time은 85 °C, 1.1 V 조건에서 120 ms로 보고되었다.”

## 검색용 별칭

사용자는 한국어, 영어, 약어로 질문할 수 있습니다. 검색용 문자열만 별칭 사전으로 정리하며 사용자가 입력한 질문 자체는 바꾸지 않습니다.

| 검색용 한국어 별칭 | 영어 표기 예시 |
|---|---|
| 보존 시간 | retention time |
| 리프레시 간격 | refresh interval |
| 프로그램·소거 | program/erase |
| 전하 포획 | charge trapping |
| 대역폭 | bandwidth |
| 정정 지연 | correction latency |

이 표는 기존 표기 규칙을 가져온 초기 사전이며, 반도체 전체에 적용되는 번역 표준은 아닙니다. 관리자가 분야와 문맥을 확인해 용어·동의어를 관리합니다.

## 사내 LLM과 DB 연결

공통 답변 지침에 다음 규칙을 포함합니다.

> 설명은 한국어로 작성하되 반도체 전문 용어는 근거 문헌의 영어 표현을 유지한다. 동일 개념에 대해 승인된 용어 사전의 대표 영어 표기를 사용하되, 직접 인용문은 원문 그대로 보존한다. 불확실한 약어를 임의로 풀거나 서로 다른 개념을 합치지 않는다. 수치·단위·기호·부정·가능성 표현의 의미를 변경하지 않는다.

운영 DB의 `terminology_entries`에 ID, 대표 영어 표기, 동의어 JSON, 검토 상태, revision과 작성자·시각을 저장합니다. `terminology_revisions`는 불변 변경 이력, `terminology_meta`는 승인 사전 버전과 최초 가져오기 상태를 보관합니다. 사전은 편집 규칙이며 과학적 근거로 인용하지 않습니다. 이전의 검색 연관어·분야·사용 주의점 컬럼은 이력 호환을 위해 남겨 두지만 입력·검색·LLM 지침에는 사용하지 않습니다.

원문은 사전과 분리하여 유지합니다. 사전을 갱신해도 원문·과거 답변을 다시 쓰지 않습니다. 답변 실행 trace에 `terminology_revision`, 각 검색의 해석 결과, 각 모델 호출의 관련 용어 snapshot을 기록합니다. Unicode NFKC 정규화는 비교에만 쓰며 HfO₂ 같은 저장 표기는 보존합니다.

## 앱에서 관리

왼쪽 **용어 사전** 메뉴(`#dictionary`)에서 대표 용어와 동의어를 묶어 관리합니다. 검색, 상태 필터, 등록, 수정, 변경 이력과 적용 확인을 제공합니다. 12개씩 표시하고 편집 창의 닫기·저장은 스크롤과 분리합니다. 입력 내용은 대표 용어·동의어 두 가지이며 검토 상태는 별도 관리합니다.

- 모든 로그인 사용자는 조회와 신규 용어 제안이 가능합니다. 일반 유저의 제안은 `draft`로만 저장됩니다.
- 관리자와 슈퍼 유저(`manage_knowledge`)는 수정·승인·보관·재승인할 수 있습니다. API에서도 권한을 확인합니다.
- `approved`만 검색과 LLM 지침에 적용합니다. `archived`는 적용에서 제외하되 이력을 남기며 재시작 시 다시 가져오지 않습니다.
- 동의어는 같은 개념만 연결합니다. `reliability`와 `retention`처럼 연관성만 있는 개념은 동의어로 합치지 않습니다. 검색 연관어의 별도 입력과 확장은 제거했습니다.
- 승인 용어 간 대표 표기·동의어 충돌은 저장을 거절합니다. 문맥마다 다른 약어는 무조건 승인하지 말고 의미를 구분합니다. 동시 편집은 revision 충돌로 보호합니다.
- 단위만 있는 항목은 등록할 수 없습니다. Vth·HfO₂ 같은 parameter·재료명은 허용하며 수치·단위 자체는 기존 수치 기능에서 관리합니다.

`GET/POST /api/pilot/terminology`, `GET/PUT /api/pilot/terminology/{id}`, `POST /api/pilot/terminology/preview`를 사용합니다. 조회에는 q/status/offset/limit을 지원합니다. 생성 요청 UUID를 재사용하면 같은 요청의 중복 저장을 방지합니다.

## 실제 검색·LLM 연결과 비용

`backend/terminology.py`가 공통 규칙을 제공합니다. 연구 질문은 대표 용어·동의어를 키워드 검색에 반영하고 원래 질문은 vector 검색과 reranker에 유지합니다. 사전 목록은 대표 용어와 동의어로만 찾습니다. 논문 목록과 Wiki 목록 검색은 입력 원문 또는 대표 용어로 해석한 표현을 찾습니다. 전문가의 담당 논문 범위는 사전 때문에 넓어지지 않습니다.

Wiki compile, 답변의 계획·보완·검토·생성, LLM lint에는 해당 입력에서 발견한 **승인 용어 최대 24개, 6,000자**만 추가합니다. 공통 Wiki 지침과 함께 읽으며 원문·제목·Figure/Table·수치·단위는 보존하도록 지시합니다. 관련 용어가 없으면 추가 입력이 없습니다. 생성 결과를 일괄 정규식 치환하지 않으며 표기 문제는 lint가 검토하도록 합니다.

사전 수정은 전체 Wiki 재생성이나 embedding 재계산을 예약하지 않습니다. 다음 검색·답변에서 즉시 읽고, Wiki는 다음 수동/신규 자료 갱신 시 관련 용어 fingerprint가 달라진 LLM 문서만 재작성합니다. LLM 미연결 상태의 근거 링크 문서는 사전 수정으로 재작성하지 않습니다. 정기 lint는 변경된 승인 사전을 인식하되 기존 호출·입력 한도를 지킵니다.

현재 사내 LLM API가 미연결이므로 실제 사내 모델의 용어 준수 품질은 아직 검증하지 않았습니다. 로컬 검색과 사전 저장·권한은 실제 DB로 동작하고, LLM 연결 경로는 테스트 응답으로 검증합니다.

## 수치와 scientific notation

현재 실제 DB 앱의 `src/scientificNotation.ts`가 claim·연결 수치·조건·Wiki와 답변 복사에 공통 표시 규칙을 적용합니다.

- `1.20e-3`, `1.20 × 10^-3`는 `1.20 × 10⁻³`로 통일합니다. 명시된 소수 끝자리 0은 유효숫자로 보존합니다.
- 절댓값이 10,000 이상 또는 0보다 크고 0.001 미만인 일반 숫자는 scientific notation으로 표시합니다. `65000`, `65k`는 `6.5 × 10⁴`입니다. `0.9 V`, `90 °C` 같은 값은 읽기 쉬운 일반 표기를 유지합니다.
- 명시적인 `cm^2`는 `cm²`, 음수 부호는 `−`, `µ`는 `μ`로 통일하고 부등호·범위·단위를 유지합니다. 단위 환산이나 임의의 반올림은 하지 않습니다. 단위 없는 배율 `0.19x`는 `0.19×`입니다.
- 원문 인용, 원본 PDF, DB의 `raw_value`는 변경하지 않습니다. 계산·필터에는 `numeric_value`와 단위·부등호를 사용하고 표시용 문자열로 계산하지 않습니다.
- OCR에서 지수가 사라진 `10 2`, 화학식 `HfO2`처럼 뜻이 불명확한 문자열은 추측해서 고치지 않습니다. 원본 PDF를 확인해 구조화 값을 교정해야 합니다.

`backend/scientific_values.py`는 구조화 적재 시 명확한 단일 scientific 값과 `numeric_value`를 대조하고 불일치 시 적재를 취소합니다. 범위·손실된 지수의 과학적 의미를 자동 판정하는 검증은 아닙니다. 현재 저장된 141개 수치에서는 이 검사에 걸리는 불일치가 없습니다.

사내 LLM 추출 지침에도 원문 표기·계산용 값·단위·비교 연산자·유효숫자·근거를 분리하고 지수를 원본과 대조하도록 추가합니다. 표시 정규화가 추출 오류를 은폐하거나 원문 인용을 재작성해서는 안 됩니다.

## 초기 목업과 호환

`shared/terminology.json`은 대표 영어 표기와 검색용 별칭입니다. `src/terminology.ts`는 질문 분류·논문 검색에만 적용합니다. 화면의 가상 답변은 문맥을 확인해 직접 수정했고, 원문 인용과 수치는 변경하지 않았습니다.

실제 앱은 DB 사전을 사용합니다. `shared/terminology.json`은 DB 최초 가져오기 자료이자 이전 가상 목업의 호환 자료이며, 앱에서 수정한 용어를 이 파일로 덮어쓰지 않습니다.
