# 전문가 지식의 구성과 갱신

전문가는 이름만 바꾼 질의 라우터가 아니라, 담당 논문과 공통·특화 지식을 가진 연구 관점입니다. 현재 구현은 [DB 구성](DATABASE_PLAN.md), [Markdown Wiki](MARKDOWN_WIKI.md), [연구 QA](RESEARCH_QA.md)에 연결됩니다.

## 생성과 담당 범위

관리자와 슈퍼 유저는 이름·개요·사용 여부·논문 분류 조합을 설정합니다. 같은 축에서 선택한 값은 합집합, 서로 다른 축은 교집합입니다. 제목·초록 등의 fingerprint가 같은 논문은 분류를 재사용합니다. 생성 전에 연결 논문·claim·재사용 가능한 공통 Wiki 수를 확인합니다. 실제 사용 가능한 공통 Wiki만 집계하고 내부 분할 문서·자동 목차는 지식 수에서 제외합니다.

새 전문가는 기존 논문과 claim을 다시 추출하지 않습니다. 담당 범위에 속하는 논문과 모든 근거가 그 범위에 속하는 공통 Wiki를 연결하고 전문가 index를 생성합니다. 자동 분류 규칙과 관리자의 포함·제외 설정을 재사용하며, 분류 점수를 검증된 확률로 해석하지 않습니다. 모호한 논문의 LLM 자동 판정·고도화된 검토 큐는 추가 구현 범위입니다.

## 공통 Wiki와 특화 Wiki

| 층 | 내용 | 재사용 방법 |
|---|---|---|
| 공통 원천 | 한 논문의 선별 claim·parameter·수치·조건·원문 위치 | 여러 전문가가 같은 원천 지식을 공유 |
| 공통 주제 | 여러 논문의 합의·차이·조건·한계·미해결 질문 | 전체 근거가 담당 범위에 포함될 때 사용 |
| 전문가 index | 개요와 유효한 담당 지식 링크 | LLM 없이 생성하는 탐색 목차 |
| 전문가 특화 주제 | 명시적으로 요청한 주제에 대한 담당 범위 내 종합 | 필요할 때만 생성하며 다른 전문가의 지식으로 자동 편입하지 않음 |

본문은 사용자에게 이해되는 사실을 중심으로 쓰고, 실험 사실·저자 해석·모델 추정의 차이는 근거와 검토 상태에서 구분합니다. 서로 다른 조건의 숫자를 단순 순위로 비교하지 않습니다. 작성 지침은 `backend/prompts/wiki_policy.md` 하나이며 ingest·답변·lint가 실제로 읽습니다. 목록은 검색·접기·페이지 이동으로 제한하고 전체 Wiki를 질문마다 모델에 보내지 않습니다.

## 지속 갱신

새 PDF → 원문 추출·분류 → 전문가 자동 편입 → 변경된 공통 원천·주제 갱신 → 의존하는 전문가 index·특화 문서 갱신 → 검색 색인 갱신 순서입니다. 파일·원천·정책·지침·모델 식별자의 hash가 같으면 기존 결과를 재사용합니다. 원천이 바뀐 문서는 최신화 전까지 답변 근거에서 제외합니다. `raw/` 감시는 앱 실행 중 60초 간격이며 오류는 작업 현황에서 확인합니다.

수동 재실행은 관리자만 가능합니다. 전문가 설정의 공통 Wiki 갱신과 각 전문가의 갱신 버튼은 범위를 나눠 처리합니다. 갱신·lint·변경 이력은 자동 생성 결과의 과학적 정확성을 보증하지 않으며 근거 검토가 필요합니다.

전문가 삭제 시 공용 원천 데이터와 공통 Wiki는 보존합니다. 전문가 전용 문서는 활성 검색에서 빠지며 버전과 삭제 기록을 남겨 실행 취소를 지원합니다. 다른 전문가가 삭제된 전문가의 특화 Wiki를 자동으로 가져오지는 않습니다. 재사용 가치가 있는 내용은 공통 주제로 근거를 확인해 정리하는 것이 원칙입니다.

## 질문과 답변

자동 추천 또는 직접 선택 → 대화 문맥 확인 → 담당 범위의 Wiki·claim·원문 검색 → 연결 수치·조건 조립 → 보완 검색 → 종합 답변·전문가별 관점 → 진술·인용 검증으로 진행합니다. 답변마다 참여 전문가를 표시하고 후속 질문을 같은 대화에서 이어갑니다. 이전 답변은 질문의 대상을 해석하는 문맥일 뿐 독립된 사실 출처가 아닙니다.

진행 화면은 실제 검색·답변 작성·검증 단계만 보여줍니다. 중지는 연결을 끊고 이후 단계 실행을 막습니다. 이미 사내 API가 처리 중인 요청 자체의 서버 연산 취소는 제공자 지원이 필요합니다.

## 비용과 추가 설계

질문 빈도는 유용한 Wiki 주제를 찾는 수요 신호가 될 수 있지만 사실의 신뢰도나 논문의 중요도를 뜻하지 않습니다. 현재 질문·답변 기록을 자동으로 Wiki 원천에 편입하거나 질문 빈도에 따른 Wiki 자동 개편을 실행하지 않습니다. 도입 시 비공개 질문 제외, 개인 식별 정보 제거, 최소 집계 기준과 원문 재검색이 필요합니다.

대량 논문 환경에서는 공통 종합 재사용·변경분만 갱신·검색 예산을 먼저 측정합니다. 최신 주목 논문이나 이슈 선정은 별도 평가 가능한 기준이 필요하며 단순 조회 수·질문 수로 구현 완료된 기능이 아닙니다.
